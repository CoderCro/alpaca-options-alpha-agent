## Strategy defined (user-specified)
- **Watchlist**: human-approved; agent may recommend additions. US stocks with market cap >= $10B; SPY, SPX, QQQ (QQQ substitutes for NDX -- Alpaca doesn't support NDX index options, confirmed against their docs); crypto limited to BTC, ETH, LINK
- **Trading list**: >=2 of 4 criteria -- (1) support/resistance via weekly touches with daily chart prepping a 3rd touch, (2) multi-timeframe trend alignment (HH/HL on daily/4h/15m), (3) daily MA20/50/100 acting as strong S&R, (4) monthly candle closing above the weekly-timeframe MA10
- **Blackout rules**: no trades +/-2h around the 9:30 ET open; no trades day-before/of/after Tier-1 macro news (FOMC, NFP)
- **Verified fact**: none of 2026's FOMC meetings fall in the hackathon week, but NFP (August jobs report) lands exactly on **Sep 4 — the submission deadline day**. Our own blackout rule therefore forbids new trades on Sep 3-4, so real P&L needs to be built by end-of-day Sep 2.
- **Featherless's role**: bounded to (a) a pre-trade veto gate that can only block, never originate, a trade, and (b) plain-language reasoning narration for the dashboard/write-up. It never picks structure/size, never bypasses filters, has no order-placement access, and fails closed (treats unparseable output as a veto).
- **Exit ladder** (user-specified in detail): sell 20% of the position at +20% profit; sell another 20% at +45% profit (this arms a breakeven stop on the remainder); from there it's a race — if price falls back to breakeven first, sell 50% of what's left with the final piece exiting on -20% loss or +100% profit; if +95% profit is hit before any pullback, sell 50% of what's left with the final piece's exit timing left to Featherless's discretion (sentiment + S&R). A hard 7-day-to-expiry close overrides every stage regardless of where the ladder is.

## Company C: volatility-edge strategy (later, same day)
- User asked whether an agentic workflow could be built around Jeff Yass/Susquehanna's poker-probability-applied-to-vol-pricing philosophy. Answered directly: yes conceptually, but a literal reproduction isn't buildable on Alpaca's retail API (no quoting both sides, no colocated feeds) -- translated the philosophy into concrete, buildable components (probabilistic edge, vol mispricing as the signal, delta-neutral construction, Kelly-ish sizing, risk discipline) and flagged the real constraints before writing anything.
- User chose the largest of three offered scope options (concept-only / add-a-signal / new Company C) via AskUserQuestion: a full third company, own account, own guardrails wiring.
- **Live spike before committing to the design**: fetched a real SPY option chain (worked around a sandbox TLS/cert failure reaching `data.alpaca.markets` the same way as other sandbox-network issues -- retried with the sandbox disabled). Every contract's `greeks` block came back all-zero (`delta/gamma/rho/theta/vega: 0`) and there's no implied-vol field in the snapshot at all -- confirms options_selector.py's existing delta caveat was actually an understatement. Conclusion: Company C computes its own theoretical greeks/IV (Black-Scholes) rather than trusting the feed, which is closer to what a real market maker does anyway, not a workaround.
- **Design insight surfaced before building**: `guardrails.ALLOWED_SIDES_FOR_OPEN = {"buy"}` blocks any short sale. A delta-hedged long call needs to *short* stock to hedge; a delta-hedged long put needs to *buy* stock. So Company C only ever proposes puts -- by put-call parity a delta-hedged put carries essentially the same vol exposure as a delta-hedged call, so nothing is given up, and zero new short-selling capability is introduced.
- User picked the exit rule (vol-edge reversal OR a hard 7-day-to-expiry cutoff, whichever first) over a DTE-only backstop via a second AskUserQuestion -- mirrors the hard DTE override already used in Company A/B's exit ladder.
- Built, grounded in the actual existing code (read guardrails.py/execution.py/company_config.py/run_company_b.py/company_a_agent.py/featherless_review.py/agent_tools.py first, not assumed from the README):
  - `options_math.py` -- Black-Scholes price/delta/vega + an IV solver (Newton-Raphson, bisection fallback). Tested against the textbook example ($10.4506), put-call parity, delta bounds, and arbitrage-bound fail-closed behavior. One test's own premise was wrong (deep-ITM-near-expiry IV is genuinely unrecoverable from price, vega ~0 everywhere) -- fixed the test, not the code, a real distinction worth keeping straight.
  - `vol_edge.py` -- realized vol from the underlying's own price history (`execution.get_bars`, unaffected by the OPRA block) vs. implied vol; only acts when implied is >=3 vol points cheap (the rich-implied/harvest-the-premium side can't be traded, see guardrails constraint above).
  - `delta_hedge.py` -- BS-delta-based hedge share sizing.
  - `hedge_store.py` -- links a put position to its hedge-share count; deliberately a smaller, separate shape from `position_store.py`'s scaled exit-ladder state rather than force-fitting a tranche state machine onto a strategy that only ever does one entry and one exit.
  - `guardrails.py`: additive-only `asset_class` field on `OrderRequest` (default `"option"`, A/B behavior byte-for-byte unchanged) so the stock-hedge leg's risk check skips the x100 contract multiplier.
  - `agent_tools.py`: fixed a real latent bug this change would have triggered -- `_position_max_risk`'s fallback branch (used when `cost_basis` isn't in Alpaca's position response) unconditionally applied the x100 options multiplier; harmless while every position was an option, wrong the moment a plain stock hedge position exists too. Now asset-aware (option symbols are OCC-format and always contain digits; equity tickers never do). Also added four new gated tools (`get_vol_edge_signal`, `place_delta_neutral_put`, `check_vol_edge_exit_actions`, `close_delta_neutral_position`), same guardrails-then-Featherless-veto-then-execution-then-audit chain as `place_option_order`.
  - `company_c_agent.py` + `run_company_c.py` + `.env.company_c.example` -- mechanical loop mirroring `company_a_agent.py`'s shape, trading SPY only for now given remaining time.
- **Known, flagged (not solved) gap**: the put and its stock hedge are two separate CLI calls, not atomic -- if the put fills and the hedge then fails, the position is temporarily unhedged. Handled the same way the existing vertical-spread gap is handled: logged loudly (`hedge_leg_failed` audit event), not hidden, not solved this week.
